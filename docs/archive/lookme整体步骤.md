# 步骤

> 核心原则：先复现 DeLTa 可参考代码，再用 TnT 数据集建流程，再迁移与兼容，最后再优化 Prompt。

## 一、最终目标

构建一个由 LLM 驱动的增强型决策树方案，在 TnT 涉及的经典数据集上完成可复现、可对比、可解释的实验流程，并逐步验证：

- 基于 DeLTa 思路的规则增强是否有效；
- 在 TnT 相关数据集上是否可稳定迁移；
- Prompt 优化是否带来可量化提升。

---

## 二、执行顺序

## 阶段 1：先复现并拆解 DeLTa 源码（先学会，再改造）

目标：找到 DeLTa 中可直接复用的“backbone代码”。

重点定位模块：

1. Rule Extractor（树规则提取）
2. LLM Interface（Prompt 组装与调用）
3. Gradient Net Trainer（负梯度拟合与误差修正）

当前仓库可直接对应的脚本链：

- `DeLTa-main/run_randforest.py`
- `DeLTa-main/llm/get_prompts/run_get_prompt.py`
- `DeLTa-main/llm/query/run_get_answer.py`
- `DeLTa-main/llm/get_trees.py`
- `DeLTa-main/run.py`
- `DeLTa-main/run_ensemble.py`

目前简单过了下

---

## 阶段 2：在 TnT 涉及的单一数据集上先建完整流程

目标：不是一上来覆盖所有数据集，而是先在 **一个 TnT 相关数据集** 上完成端到端闭环。

- 先选一个较为熟悉、数据准备成本最低的 TnT 数据集。
- 先跑通“训练规则 -> 组 Prompt -> LLM 输出 -> 规则落地 -> 训练与评估”。
- 每一步必须有可检查产物（日志、规则文件、结果文件）。
- 先只保证“流程完整跑通”，暂不追求最优指标。

---

## 阶段 3：迁移源代码

目标：把 DeLTa 可用部分迁移为你自己的工程化流程。

迁移原则：

1. 小步迁移：一次只迁一个模块。
2. 同步验证：迁移后立即跑最小样例。
3. 保留回退：每次改动可快速切回旧版本。

最低迁移范围：

- 规则抽取与序列化；
- Prompt 生成与规则解析；
- 负梯度/误差修正训练链路。

---

## 阶段 4：兼容与完整跑通

目标：让“迁移后的版本”在目标单一数据集上稳定可运行。

兼容检查清单：

1. 数据格式兼容（分类/回归、类别/数值特征）。
2. 规则文件兼容（LLM 输出可解析、可执行）。
3. 训练参数兼容（超参、随机种子、日志路径）。
4. 结果评估兼容（基线对比可复现）。

完成标准：

- 连续多次运行无崩溃；
- 指标输出完整；
- 有 RF 基线和迁移后模型对比结果。

---

## 阶段 5：最后再做 Prompt 优化

目标：在“已经跑通”基础上做性能改进，而不是在流程未稳时提前调 Prompt。

优化输入来源：

- `tabular_data_generation.pdf` 的 **P6**；
- `tabular_data_generation.pdf` 的 **最后一页 Prompt**。

优化策略：

1. 固定其他变量，只改 Prompt；
2. 记录每版 Prompt 对应指标；
3. 采用 10 次均值，避免偶然波动误判。

---

## 三、当前 ToDo（按优先级）

- [ ] 完成 DeLTa 关键模块映射表（脚本、输入、输出、依赖）。
- [ ] 选定一个 TnT 单一数据集并跑通端到端流程。

---

## 四、风险与约束

1. 若未先跑通流程就优化 Prompt，会导致调参无效。
2. 若一次迁移过多模块，排错成本会指数上升。
3. 若单一数据集都不稳定，多数据集扩展没有意义。
4. Prompt 优化必须在可重复实验框架下进行，否则结论不可用。
